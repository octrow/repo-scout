# repo-scout

Методика: `~/dev/docs/repo-triage.md` (стоп-правила, флаги, баллы, Шаги 1–3, формат результата). Прочитай её перед началом.
Скрипт `~/dev/repo-scout/scout.py` делает Шаг 1 механически: поиск, стоп-правила, флаги, общие баллы (свежесть + популярность).

## Порядок

1. **Что ищем.** Сформулируй задачу в 1–2 фразы. Если в проекте есть `<проект>/docs/repo-triage.md` с проектными осями и порогом, возьми их.
2. **Запросы.** 3–6 вариантов: синонимы, англ. термины, `language:`, `topic:`, `in:readme`. Мало звёзд не повод отсекать, поэтому `stars:` не ставь.
   ```bash
   ~/dev/repo-scout/scout.py "whisper live transcription" "speech to text overlay language:python" "topic:asr linux"
   ```
   По умолчанию берутся репо с push за последние 6 мес (`--months`), флаг `новый` = создан ≤ 60 дн (`--new-days`). `--all` показывает отсеянных, `--json` для дальнейшей обработки.
3. **Проектные оси.** Для прошедших стоп-правила добавь баллы по осям проекта (платформа, стек, фичи). README читай только если без него не решить: `gh api repos/OWNER/REPO/readme -H 'Accept: application/vnd.github.raw' | head -c 15000`, лучше grep по ключевым словам.
4. **Шаг 2 (Осмотр)** для лучших 3–7, по методичке: без клонирования, с бюджетом токенов. Цель Разбора уточняй у пользователя.
5. **Результат.** Строки-сводки в формате методички (`триаж: шаг 1 · баллы … · вердикт: …`). Детали Шагов 2–3 — в `<проект>/docs/analogs/<repo>.md`.
