# repo-scout

Методика: `docs/repo-triage.md` (стоп-правила, флаги, баллы, Шаги 1–3, формат результата). Прочитай её перед началом.
Команда `repo-scout` делает Шаг 1 механически: поиск, стоп-правила, флаги, общие баллы (свежесть + популярность).

## Порядок

1. **Что ищем.** Сформулируй задачу в 1–2 фразы и запиши **Описание задачи на английском** (1–3 фразы, что нужно; переведи с русского): по нему считается Близость. Если в проекте есть `<проект>/docs/repo-triage.md` с проектными осями и порогом, возьми их.
2. **Запросы.** 3–6 вариантов: синонимы, англ. термины, `language:`, `topic:`, `in:readme`. Мало звёзд не повод отсекать, поэтому `stars:` не ставь.
   ```bash
   repo-scout --task "Find open-source live speech transcription with an overlay, runs on Linux" "whisper live transcription" "speech to text overlay language:python" "topic:asr linux"
   ```
   `--task` обязателен: без него команда не запустится. Результат отсортирован по Близости (колонка `близ`), строки ниже порога `--min-closeness` (по умолчанию 0.64) отсеяны как «не по теме»; при слишком узком или широком результате переформулируй задачу, а не порог. `--lang python` добавляет `language:python` к каждому запросу. К запросам автоматически добавляются `in:name,description,topics,readme` и `mirror:false`. По умолчанию берутся репо с push за последние 6 мес (`--months`), флаг `новый` = создан ≤ 60 дн (`--new-days`). `--all` показывает отсеянных, `--json` для дальнейшей обработки (формат `{"rows": [...], "dropped_by_must": [...]}`). `--exclude REGEX` и `--must REGEX` (повторяемые, без учёта регистра) задают запрещённые и обязательные слова.
3. **Проектные оси.** Для прошедших стоп-правила добавь баллы по осям проекта (платформа, стек, фичи). README читай только если без него не решить: `gh api repos/OWNER/REPO/readme -H 'Accept: application/vnd.github.raw' | head -c 15000`, лучше grep по ключевым словам.
4. **Шаг 2 (Осмотр)** для лучших 3–7, по методичке: без клонирования, с бюджетом токенов. Цель Разбора уточняй у пользователя.
5. **Результат.** Строки-сводки в формате методички (`триаж: шаг 1 · близ 0.81 · баллы … · флаги: … · вердикт: …`). Детали Шагов 2–3 — в `<проект>/docs/analogs/<repo>.md`.
