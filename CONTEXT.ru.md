# repo-scout — глоссарий

Методика триажа: [`docs/repo-triage.ru.md`](docs/repo-triage.ru.md).

- **Кандидат** — репозиторий GitHub, найденный поиском и ещё не прошедший Отсев.
- **Отсев** (Шаг 1) — механическая проверка кандидата по метаданным: стоп-правила, флаги, баллы. Без чтения кода.
- **Стоп-правило** — условие, при котором кандидат выбывает сразу, без баллов (мёртвый, игрушка, нет кода).
- **Флаг** — пометка, которая не выбивает кандидата, а сообщает о нём (форк, stars≫commits, archived, новый, шаблон, только косметика, всплеск★).
- **Новый** — создан не более 60 дней назад. Флаг, а не балл.
- **Осмотр** (Шаг 2) — чтение страниц GitHub без клонирования; итог — вердикт и цель Разбора.
- **Разбор** (Шаг 3) — клон в `external_examples/` и чтение кода под конкретную цель.
- **Без LLM** — Поиск, Отсев, Близость и ранжирование работают без генеративных моделей: детерминированные правила, GitHub API и локальные эмбеддинг-модели (CPU, офлайн). Генеративная модель допускается только опционально и только до поиска — для Черновика Запросов; на выдачу она не влияет, и без неё всё работает.
- **Описание задачи** — 1–3 фразы на английском о том, что нужно пользователю (агент переводит с русского). По нему считается Близость.
- **Потребность** — то, что человек хочет найти, своими словами на любом языке, без названий готовых решений. Из неё получаются Описание задачи и Запросы (агентом, человеком или Черновиком LLM).
- **Черновик LLM** — Описание задачи, Запросы и Жёсткие условия, которые генеративная модель предлагает по Потребности. Только заполняет форму; человек правит и сам запускает поиск.
- **Запрос** — строка в синтаксисе GitHub search (ключевые слова, `language:`, `topic:`). Из одного Описания задачи получается несколько Запросов.
- **Пул** — кандидаты одного запуска без дублей: живая выдача всех Запросов плюс совпадения из Индекса по Близости.
- **Прогон** — один запуск поиска: Описание задачи, Запросы, Жёсткие условия, дата и итоговая таблица кандидатов (с отсеянными). Сохраняется целиком и служит черновиком для следующего поиска.
- **Индекс** — локальное накопительное хранилище кандидатов, которые уже прошли стоп-правила и для которых скачан README (метаданные + вектор). Пополняется только тем, что скачано при поисках; массовой выкачки нет. Метрики найденных в Индексе обновляются перед Отсевом.
- **Второй круг** — Запросы, которые скрипт сам строит из `topics` топ-кандидатов первого прохода. Ровно один круг, с лимитом числа Запросов.
- **Близость** — семантическое сходство кандидата с Описанием задачи. Не балл: работает как порог (ниже — стоп-правило «не по теме») и как главный ключ сортировки. Баллы методички (свежесть, популярность) — второй ключ.
- **Жёсткое условие** — требование из Описания задачи, проверяемое детерминированно: язык, обязательные слова (группы, по README и topics), запрещённые слова. Нарушение — стоп-правило; если README нет, обязательные слова не отсеивают, а дают флаг.
- **Золотой набор** — Описание задачи, Запросы и Жёсткие условия одного прошлого поиска плюс репо с известными вердиктами (из разборов проекта; клон в `external_examples/` без разбора = «→ Разбор»). Хранится вместе со снимком ответов GitHub и его датой, чтобы прогоны были сравнимы.
- **Содержательный коммит** — коммит в основной ветке, который не от служебного бота (dependabot, renovate, github-actions и т.п.) и не косметика по сообщению и размеру (docs/deps/ci/bump/typo, крошечные правки текста). Коммиты AI-агентов (Claude, Copilot, Codex, Devin…) — обычные, судим по содержанию. Свежесть и «мёртвый» считаются по последнему содержательному коммиту.
- **Только косметика** — флаг: среди последних 20 коммитов нет ни одного содержательного.
- **Вердикт** — итог Осмотра или Разбора по кандидату для конкретной задачи проекта, с датой: «→ Осмотр», «→ Разбор (цель)», «отсев (причина)», «спорно (что уточнить)». Привязан к задаче, а не к репо: у одного репо в разных задачах разные Вердикты. Хранится в Индексе и показывается при следующих поисках, но никого не скрывает.
- **Шум** — кандидаты, которые не являются проектом-основой: awesome-листы, tutorial, demo, homework, spam/promo. Отсеиваются только при ≥2 независимых сигналах (имя, описание, topics). Шаблоны — не Шум, а Флаг.
